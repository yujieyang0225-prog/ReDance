How the rehab system runs

End-to-end flow on branch Combination: a motion source produces normalized features, one shared classifier names the movement, the game scores it, and the results drive the GUI, the instruction video, and (in sensor mode) the avatar.

Hardware Python process / code Shared JSON file (30 ms atomic writes) What the user sees

Stage 1 · Motion source — pick one with live_action.py --mode …

--mode live · sensors

ESP32 + 4 IMUs

lumbar 0 · clavicular 1 · thighL 3 · thighR 4
serial 115200 baud, ~60 Hz

parse_line() · keep line if all REQUIRED_CHANNELS (IMUs 0/3/4) present

mapping.py

2 s neutral calibration → gravity & yaw axis detected → MovementMapper turns accel tilt + lumbar gyro into features

--mode mujoco · avatar

MuJoCo viewer keys

1–5 each queue ONE repetition
turn L / turn R / lean / leg L / leg R · 0 reset

sine rep 2 s + 0.4 s neutral gap → joint angles → mj_forward

run_professional_rehab.py

animates the avatar, publishes joint angles (torso rotation / bend, both hips, in degrees)

mujoco_motion.json

read by MujocoMotionClassifier: 2 s baseline, angles ÷ max range → features · stale > 0.5 s = “waiting”

--mode simulate · keyboard

Simulator keys

Q neutral · W lean · E/R lifts · T/Y turns

SimulationClassifier

maps each key straight to full-strength features — for testing the game without hardware

all three sources emit the same normalized features
{lean, lift_L, lift_R ∈ [0,1] · turn ∈ [−1,1], + = right}

Stage 2 · One shared recognition pipeline (identical for sensors and avatar)

classify.py · ActionClassifier

tilt actions beat turns (yaw cross-talk lockout) · tilt gate 0.45 · turn gate 0.35 · 5-sample debounce → ONE label:
NEUTRAL · LEAN · LIFT_L · LIFT_R · TURN_LEFT · TURN_RIGHT

new label edge (NEUTRAL → action) counts as one move

game.py · SequenceGame

required order: LEAN → TURN LEFT → LIFT RIGHT → TURN RIGHT
+10 per correct step · +50 completion bonus · wrong move resets the sequence

classifier thread writes state + label + features + score

live_state.json

the single source of truth every display reads

Stage 3 · Feedback to the user

Recognition window

big movement label · four feature bars · score, rounds & sequence progress · event flashes (+10 / reset / +50)

Instruction video panel

loops the video segment matching the current label (VIDEO_SEGMENTS_SECONDS in live_action.py)

⮌ Live-mode loop — press L in the MuJoCo viewer

The viewer reads live_state.json and drives the avatar from the recognized label and feature strength — so in --mode live the avatar mirrors the person wearing the sensors. Don’t combine L with --mode mujoco: the avatar would be recognizing its own motion.

Timing summary: sensors stream ~60 Hz · both JSON files are written atomically every 30 ms · calibration holds 2 s · one avatar repetition = 2 s sine + 0.4 s neutral gap · classifier commits a label after 5 consistent samples (~100 ms). All left/right labels are in the wearer’s / avatar’s own body frame; the on-screen camera faces the avatar, so the view is a mirror.
